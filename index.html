01. Overview

プロジェクト概要 Overview

開発背景 Background

旅行の計画時、点在するグルメ・カフェ・観光地の情報を一つずつ調べ、動線を組む手間を解決したいと考えました。地図での店舗検索から、最適な動線の旅行ルート推薦、予約までを一箇所で行える統合サービスを目標に企画しました。

開発目的 Purpose

  • Servlet/JSP + Oracle による MVC Webアプリ の設計・実装力を証明
  • 外部API(Google Maps/Places)連携と 推薦アルゴリズム の設計経験
  • 4人チームでの 協業(Git) と機能統合の経験

プロジェクト範囲 Scope

会員登録・メール認証・ログイン ID／パスワード検索 カテゴリ別の地図店舗検索 お気に入りの追加・削除 テーマ別のおすすめルート マイ旅行ルート(お気に入り巡回) 店舗予約＆レビュー 多言語(韓/英/日)

担当役割 Role

  • 認証・権限 (jBCrypt・セッション)
  • 推薦ルートアルゴリズム
  • 地図/Places 連携・お気に入り
  • 管理者の店舗登録

06. Core Feature 01

おすすめ旅行ルート 推薦アルゴリズム

★ 担当のコア機能

推薦パイプライン

Recommendation Pipeline (推薦の流れ)

1. 候補選定 (テーマ・単一地域)

都市/カフェ/自然のテーマと 単一の地域 内だけで店舗候補を取得 → 国・都市をまたぐ動線を防止

2. 重複除去 (Dedup)

シードデータと Google のお気に入りで重複保存された同一店舗を 名前基準 で除去

3. 選定 (多様性 + 評価)

カテゴリの ラウンドロビン で多様性を確保 + 評価順に上位N件を選定

4. 動線最適化 (NN + 2-opt)

最近傍法 で初期経路 → 2-opt で交差を除去し移動距離を短縮

dist = Haversine(lat1,lng1, lat2,lng2)

5. 表示 (サムネイル・移動距離/時間)

区間ごとの距離・所要時間(徒歩/車の推定)とサムネイルをカードで提供

2-opt 動線最適化 最適化

交差する経路を入れ替え、総移動距離を短縮します。

コアポイント

  • 単一地域に限定し 現実的な動線
  • Haversine + 2-opt で 移動距離を最小化
  • 移動時間の計算部を 分離設計
    (実道路APIへ差し替え可能)
  • お気に入り店舗で マイ旅行ルート を自動生成

09. Troubleshooting

トラブルシューティング＆改善 Troubleshooting

推薦ルートが国をまたぐ

課題 — 地域未指定時にソウル・東京が1コースに混在し非現実的な動線

解決 — コントローラで 単一地域を強制 + 全地域フォールバックを削除

同じ場所が2回推薦される

課題 — シードデータと Google のお気に入りで同一店舗が重複保存

解決 — 推薦段階で 名前基準の重複除去(dedup) を適用

ログインが繰り返し失敗

課題 — ログインSQLが status='ACTIVE' を参照するが列が欠落

解決 — users.status 列を追加(DEFAULT 'ACTIVE')して正常化

認証情報のソース露出リスク

課題 — APIキー・DB・メールのパスワードがコードにハードコード

解決 — 環境変数に分離(System.getenv) + 露出したキーを破棄

改善・今後の計画 Future

移動時間を実道路API(Directions)に差し替え ドラッグでルート順を直接編集 決済連携など予約の高度化
